# Build report — 2026-10-06

## Outcome: BLOCKED

The standalone Windows command has been built and installed, but the sample DiskWala share does **not** resolve to a public media URL. The public website shows metadata and instructs viewers to use the app. Its first-party metadata endpoint rejects a plain request with HTTP 400 `Missing Appicrypt header`. The official Windows app's packaged web code references `/desktop/np_lelo` and processes its returned file information as encrypted data, including the media URL. The desktop route gives 404 in an ordinary browser. This is an app access boundary, not an expired test share or a broken direct downloader. No app cryptogram or encrypted response handling was copied or bypassed.

## Resolver and endpoint evidence

1. `GET https://www.diskwala.com/app/6ac4fca22a52418b24b26ce2` returns HTTP 200 and a React application shell, not a media URL. In the rendered official page, the share displays a video MIME type and size, then tells viewers to open it in the app.
2. The public web bundle uses `https://ddudapidd.diskwala.com/api/v1/` and `POST /file/temp_info` with JSON `{"id":"<share ID>"}` to obtain metadata. It applies an `Appicrypt` integrity header generated by its own code. An ordinary POST without that header returned HTTP 400 `Missing Appicrypt header`. The response is not publicly usable by a plain HTTP client.
3. The official Windows beta is linked from the official website at `https://uploadfiles.revwala.com/Diskwala_Setup.exe`. It was downloaded **only for static inspection**. Windows reports its Authenticode status as `NotSigned`; the installer was **not executed or installed**. Its Electron package references `https://ud.diskwala.com`, maps `/app/<ID>` to `/file_info/<ID>`, and calls `POST /desktop/np_lelo`. The packaged renderer parses encrypted `fileInfo` and decrypts an embedded URL. The ordinary browser at `https://ud.diskwala.com/file_info/<ID>` displayed 404. No proprietary code or WASM is included in this project.
4. Rishi's reference repository was examined but not copied. Its proxy contract is `POST <DISKWALA_PROXY_URL>` with JSON `{"url":"<share URL>"}`, `x-api-key: <DISKWALA_API_KEY>`, and a JSON response with `fileInfo.url`, `fileInfo.name`, and `fileInfo.size`. The proxy server and credentials are not in the public repository.
5. No trustworthy current open-source implementation of a first-party unauthenticated media resolution path was found in the researched repositories and web results. `yt-dlp` 2026.8.19 reports the sample DiskWala URL as unsupported.

These observations establish the current blocker for this sample and public workflow. They do not prove that all DiskWala shares are inaccessible or that the app cannot download them.

## Independent implementation

- `diskwala_downloader.urls`: strict official share URL and 24-hex ID parsing.
- `diskwala_downloader.resolver`: inspect public HTML for standard `<video>`, `<source>`, Open Graph, and JSON-LD media; use a plain metadata API probe only to classify the access boundary. Parse an accessible `fileInfo` response if the provider ever makes it public. No private proxy or app protocol is used.
- `diskwala_downloader.models`: `MediaInfo` with direct/HLS selection and detectable URL expiry.
- `diskwala_downloader.download`: direct HTTP stream with Range resume, transient retries, `.part` file, size check, content-type check, atomic rename, Windows-safe names, duplicate handling; HLS via yt-dlp/FFmpeg.
- `diskwala_downloader.inspect`: safe resolver diagnostic; `--verbose` writes endpoint path and HTTP status to ignored `logs/`, never full media URLs or cookies.
- `diskwala.bat`: local venv launcher; project directory added to user PATH without removing existing entries.

## Failed approaches and next path

- A static HTML media scrape found no source because the page is a React shell.
- The official metadata API rejects a plain request lacking the app-generated integrity header.
- The official desktop web route is unavailable in an ordinary browser, and its packaged renderer handles encrypted file information.
- Generic yt-dlp has no DiskWala extractor for the tested version.
- Public third-party downloader sites and paid APIs were not used as runtime dependencies.

The most realistic permitted path is for DiskWala to publish a documented public download API or for the file owner/provider to supply an authorized direct media URL. The official DiskWala Windows or mobile app remains the supported route for app-only shares. This project can then adapt its resolver without changing the Windows command or downloader.
